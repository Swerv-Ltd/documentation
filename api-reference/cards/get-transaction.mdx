## Authorization and settlement links

A purchase authorization and settlement may have different IDs and references. Once their relationship is verified, both records show `COMPLETED` and expose optional linking fields:

- `transaction_role`: `AUTHORIZATION` or `SETTLEMENT`.
- `original_transaction_id`: on the settlement, the original authorization's public transaction ID.
- `settlement_transaction_id`: on the authorization, the settlement's public transaction ID.

Reconcile the linked records as one purchase, not two debits. Fields may appear after the initial notification and are omitted when no relationship has been verified. See [transaction reconciliation](/card/transaction-reconciliation) for examples, status handling, and delivery-order guidance.


```javascript Node.js
await swervpay.card.transaction('<CARD_ID>', '<TRANSACTION_ID>');
```

```php PHP

];

```



```go Go
package main

import (
	"context"
	"fmt"
	"github.com/swerv-ltd/swervpay-go"
	"log"
)

func main() {
	ctx := context.Background()

	client := swervpay.NewSwervpayClient(&swervpay.SwervpayClientOption{
        BusinessID: "<BUSINESS_ID>",
        SecretKey: "<SECRET_KEY>",
    })

	resp, err := client.Card.Transaction(ctx, "<CARD_ID>", "<TRANSACTION_ID>")

	if err != nil {
		log.Fatal("error", err.Error())
		return
	}
}
```
